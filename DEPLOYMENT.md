# Deploy NTT Nutrition RBM on Render

## Status and prerequisites
The GitHub repository contains application source code only. **No site or database is created by committing this file.** The Blueprint creates a **paid** web service and managed PostgreSQL database in the Singapore region.

The administrator must approve hosting and database charges, ensure institutional IT/data-security authorization, and configure a strong admin password.

## 1. Launch the Render Blueprint
Open:
https://dashboard.render.com/blueprint/new?repo=https://github.com/fandiimran3012-design/ntt-nutrition-rbm-dashboard

Select **My Workspace** and connect the GitHub repository if Render requests GitHub authorization.

Review the two requested resources:
- Web service: **ntt-nutrition-rbm**, plan **starter**, Singapore region
- PostgreSQL: **ntt-nutrition-rbm-postgres**, plan **basic-256mb**, Singapore region

Do not press **Apply** until you understand the costs and have approval.

## 2. Configure the secret
Supply RBM_ADMIN_PASSWORD at the Render Blueprint prompt. Choose a long, random password and do **not** place it in GitHub, screenshots, email, or chat. SECRET_KEY is generated by Render. DATABASE_URL is attached internally to the database.

## 3. Deploy and verify
After Apply:
- Wait for successful app and DB deployment.
- Visit the assigned https://...onrender.com URL.
- Verify **/api/health** responds with database = postgresql and status = ok.
- Open **/** in a private/incognito browser: read-only access should work.
- Open **/login**, enter the admin password, and test a small activity update.
- Open the public page from another browser and verify the change appears within approximately 15 seconds.

## 4. Migrate existing monitoring data
Before importing, open the previous *local HTML dashboard* on the computer/browser where data were originally entered. Use **Backup Data (JSON)**. Keep multiple backups in a secure institutional location.

After first production deployment, log in as editor at **/login**, then use **Import saved JSON**. Confirm IMAM, MIYCN, FSCC, SACA, activity evidence, and the five MoH calendar quarters are mapped correctly. Some legacy SACA indicators were redefined; verify archived mappings before linking records.

## 5. Security and governance
The public API removes known evidence links, internal notes, and named personal-data fields; **do not upload participant-level or sensitive information** without separately reviewing the data model and consent/authorization. This application has single-password editor authentication and basic snapshots, not enterprise SSO, audit logging, or role-based approvals.

Get UNICEF IT/Infosec approval before using this with non-public programme records. Define a regular database backup/export procedure and review service retention and billing periodically.
